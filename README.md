# Проект «Моя библиотека»

Учебное Android-приложение на Kotlin для ведения личного каталога книг. Данные хранятся локально в SQLite — регистрация, интернет и сервер не нужны.

## Возможности

- просмотр списка книг;
- добавление новой книги;
- редактирование названия, автора, года, жанра и статуса прочтения;
- удаление книги с подтверждением;
- поиск по названию, автору и жанру;
- отметка «прочитана / не прочитана»;
- отображение общего количества книг и числа прочитанных.

При первом запуске база автоматически создаётся и заполняется пятью демонстрационными книгами.

## Открытие в Android Studio

1. Распакуйте архив проекта.
2. Запустите Android Studio и выберите **Open**.
3. Укажите папку `MyLibraryAndroid` (в ней находятся `settings.gradle.kts` и `build.gradle.kts`).
4. Дождитесь синхронизации Gradle. При первом запуске потребуются интернет и установленный Android SDK: Gradle загрузит нужную версию и плагины.
5. Создайте или выберите эмулятор Android либо подключите устройство с включённой отладкой по USB.
6. Нажмите **Run**.

Минимальная версия Android — API 23. В проекте используется Android Gradle Plugin 9.3.1, Kotlin 2.4.21 и Gradle 9.5.0.

## Где реализована SQLite

- `BookDbHelper.kt` — создание базы `my_library.db`, таблицы `books`, индекса и стартовых записей.
- `BookRepository.kt` — SQL-операции чтения, поиска, добавления, изменения и удаления.
- `Book.kt` — модель одной книги.
- `MainActivity.kt` — пользовательский интерфейс и обработка действий.
- `database/schema.sql` — отдельный SQL-файл со структурой таблицы и индексом.

## Проверка работы

1. Добавьте книгу и убедитесь, что она появилась в списке.
2. Измените автора или жанр и сохраните изменения.
3. Введите часть названия или фамилии автора в строку поиска.
4. Переключите статус прочтения и проверьте счётчик в верхней части экрана.
5. Удалите запись, подтвердив действие.
6. Закройте и снова откройте приложение: сохранённые записи должны остаться.

Для учебного примера запросы выполняются непосредственно из UI-потока, поскольку база небольшая. Для промышленного приложения длительные операции с БД следует переносить с главного потока, например, в корутины/фоновый исполнитель.
